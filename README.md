# BoltCanvas BoltCanvas is a shared workspace for VEX V5 robotics teams. Keep robot configuration, autonomous routes, test evidence, engineering notes, assigned work, and competition preparation together. ## Get started You need Node.js 22.13 or newer, npm, and PostgreSQL. Docker Desktop with Compose is the easiest way to run the included local database. ```sh npm ci ``` Copy `.env.example` to `.env` (PowerShell: `Copy-Item .env.example .env`; macOS/Linux: `cp .env.example .env`). Generate a secret and put its output in `AUTH_SECRET` in `.env`: ```sh node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))" ``` The example database URLs match `docker-compose.yml`. With Docker Desktop running: ```sh npm run local ``` This starts PostgreSQL, generates the Prisma client, synchronizes the local schema, and starts Next.js. Open [localhost:3000](http://localhost:3000), create an account, complete onboarding, then create a team or join with an invite code. The app starts with an empty workspace; create your robot and tasks to populate it. If you already have PostgreSQL, set `POSTGRES_PRISMA_URL` and `POSTGRES_URL_NON_POOLING` to your database, then run: ```sh npm run db:generate npm run db:deploy npm run dev ``` `npm run local:stop` stops the Compose services and preserves the database volume. Use `npm run dev` when the database is already running and prepared. ## Work faster - **Command launcher:** press `Ctrl+K` on Windows/Linux or `⌘K` on macOS, or click the search button. Type a tool name, use the arrow keys, and press Enter. Escape closes the launcher. Choose the record search option to search team data. - **Dashboard:** open testing, autonomous planning, the build log, or the notebook in one click. The next-move panel highlights the team's next readiness action. - **Task queue:** open tasks appear first. Search by title, description, robot, or teammate; filter by assignee, high priority, unassigned work, or completion. Results sort by completion, priority, then due date. Update status directly on a task. - **Task creation:** expand “New task” to assign a next step; the form starts expanded in an empty workspace. - **Navigation:** the desktop sidebar scrolls independently. On phones, use the menu button to expand navigation and team controls. Links preserve the active team. ## Tools Robot profiles and port configuration · test records · autonomous field planning · VEXcode export · engineering calculators · build logs and notebook · team tasks and forum · event preparation · scouting, strategy, rules, and World Skills. ## Environment | Variable | Purpose | | --- | --- | | `POSTGRES_PRISMA_URL` | PostgreSQL connection for Prisma queries | | `POSTGRES_URL_NON_POOLING` | Direct PostgreSQL connection for migrations | | `AUTH_SECRET` | Random secret used by authentication | | `AUTH_URL`, `NEXT_PUBLIC_APP_URL` | App origin, `http://localhost:3000` for local use | | `AUTH_TRUST_HOST` | Host trust setting; the local example sets it to `true` | | `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `EMAIL_FROM` | Optional email delivery configuration for password resets | | `VEX_EVENTS_API_TOKEN` | Optional server-side token for official event data | | `ENABLE_LOCAL_DEV_TOOLS`, `ALLOW_DEV_RESET` | Keep `false` in production | Never commit `.env` or put database, email, authentication, or event credentials in `NEXT_PUBLIC_*` variables. SMTP and event integrations need their own configuration; see [.env.example](.env.example). ## Checks and production ```sh npm run lint npx tsc --noEmit npm test npm run build:live ``` `build:live` builds Next.js without applying database migrations. `npm run build` generates Prisma, applies migrations to the configured database, then builds. For a prepared production environment, use `npm run start` after building. Review [DEPLOYMENT.md](DEPLOYMENT.md), set production database and authentication values, and run `npm run publish:check` before publishing. ## Project layout ```text src/app/                Next.js App Router pages, layouts, and API routes src/components/app/     Robotics tools and shared workspace UI src/components/auth/    Account forms and authentication layout src/lib/                Actions, authorization, services, and robotics logic src/app/productivity.css Workspace redesign and responsive interaction styles prisma/                 Database schema and migrations tests/                  Node test suites public/                 Static assets ``` Built with Next.js 16, React 19, TypeScript, Prisma, PostgreSQL, Auth.js, Tailwind CSS, and Lucide icons. ## Troubleshooting - **Database unavailable:** start Docker Desktop, run `npm run local:prepare`, then retry. Make sure port 5432 is available and the URLs match your database. - **Missing Prisma client:** run `npm run db:generate`. - **Port 3000 already in use:** open the port printed by Next.js and update the app/auth origins to match if using a different local port. - **No team records:** select the intended team or create/join one. Data belongs to team workspaces. - **Password reset or event data unavailable:** configure SMTP or `VEX_EVENTS_API_TOKEN` respectively. - **Contact foundedglue@gmail.com if any error this is a BETA and is in testing.
